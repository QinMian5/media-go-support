Media Go receiver API

Media Go sends audio to an endpoint you operate. The protocol uses standard multipart HTTP requests and requires durable save receipts. It does not require a persistent streaming connection.

Implement the protocol

Read the complete receiver contract, including request metadata, segment manifests, idempotency, conflict handling, and background delivery boundaries.

  • Audio: PCM16 WAV, 48 kHz, mono.
  • One configured URL handles file, segment, finalize, and test operations.
  • The metadata part is UTF-8 JSON. File operations also include a file part with audio/wav.
  • Successful persistence returns HTTP 200 and {"status":"received"}. Return this only after the audio and required metadata have been saved.
  • A connection test returns HTTP 200 and {"status":"ok"}, without storing media.
  • Optional authentication uses the complete Authorization header configured by the user.

Privacy and access

Use HTTPS for public endpoints. You manage access, retention, processing, and deletion on your own receiver. Configure those rules before sending real recordings. The developer's dedicated Apple review receiver is restricted to short test audio and is not supplied as a shared server for normal use.
